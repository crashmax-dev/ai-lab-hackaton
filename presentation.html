■ ■ ■01_what_is_local_llm.md

Что такое local LLM

Local LLM — языковая модель, которая запускается локально: на ноутбуке, рабочей станции, сервере или edge-устройстве, а не в облаке.

Главная идея: модель работает у вас, а не на удалённом API.

Что даёт local LLM

  • офлайн-работу;
  • контроль над данными;
  • отсутствие оплаты за каждый запрос;
  • низкую задержку в простых сценариях;
  • возможность тонкой настройки под свои задачи.
# модель целиком лежит на вашем диске
$ ls -lh ~/models
qwen2.5-7b-q4_k_m.gguf   4.7G  ← и это вся «инфраструктура»
■ ■ ■02_local_vs_cloud.md

Local LLM vs Cloud LLM

local LLM
  • работает на вашем железе;
  • данные не уходят во внешний сервис;
  • зависит от RAM/VRAM/CPU;
  • обычно дешевле в долгую при постоянной нагрузке.
cloud LLM
  • работает на удалённой инфраструктуре;
  • проще стартовать;
  • обычно мощнее по качеству;
  • есть цена за токены и зависимость от интернета.

Коротко

Cloud — проще и сильнее «из коробки».
Local — дешевле, автономнее и контролируемее.

■ ■ ■03_open_vs_proprietary.md

Open source LLM vs proprietary LLM

open source / open-weight
  • веса доступны для скачивания;
  • можно запускать локально;
  • можно использовать разные runtime;
  • часто можно дорабатывать и квантовать.
proprietary
  • модель и веса закрыты;
  • доступ обычно только через API;
  • меньше свободы;
  • часто выше качество у топовых моделей.

Вывод

Open-weight модели — основа local LLM.
Proprietary — чаще cloud-first история.

Llama · Qwen · Mistral (Apache 2.0) · Gemma · Phi · DeepSeek — открытые веса; GPT / Claude / Gemini — закрытые.

■ ■ ■05_quantization.md

Квантование (quantization)

Quantization — сжатие весов модели, чтобы она занимала меньше памяти и запускалась быстрее.

Типичные уровни

  • FP16 — больше памяти, выше качество;
  • INT8 — компромисс;
  • 4-bit — самый популярный баланс для local LLM;
  • 3-bit и ниже — ещё меньше памяти, но качество падает.
практика

Для локального запуска чаще всего берут Q4_K_M или похожие 4-bit варианты.

Qwen2.5-7B: FP16 ≈ 15.2 ГБ → Q4_K_M ≈ 4.7 ГБ

■ ■ ■06_why_quantization_matters.md

Почему квантование важно

без квантования
  • модель может не поместиться в память;
  • inference будет слишком медленным;
  • стоимость железа резко растёт.
с квантованием
  • модель запускается на более доступном железе;
  • можно работать на CPU, iGPU, NPU или consumer GPU;
  • проще масштабировать на офисные машины.

Малые модели (1–3B) теряют от квантования сильнее, чем 7B+. Правило: 7B в 4-bit обычно лучше, чем 3B в FP16.

■ ■ ■08_best_models.md

Best local LLM по классам

Рекомендуемые варианты по состоянию на 2026:

  • До 2B: Phi-family, Gemma mini-класс;
  • До 7B: Qwen, Llama, Gemma, Mistral small-класс;

■ ■ ■11_setup_lmstudio.md

Как настроить local LLM в LM Studio

Шаги

  1. установить LM Studio (lmstudio.ai);
  2. открыть каталог моделей;
  3. выбрать GGUF-модель;
  4. скачать нужную квантованную версию (Q4_K_M);
  5. загрузить модель;
  6. включить local server;
  7. подключить приложение через localhost.
плюс
  • удобно тестировать разные модели;
  • легко сравнивать качество;
  • не нужен терминал.
# CLI опционально
$ lms server start
$ lms load qwen2.5-7b-instruct
# сервер: http://localhost:1234/v1

■ ■ ■13_intel_openvino.md

Intel stack: OpenVINO

OpenVINO — ключевой стек для Intel.

Он нужен, когда вы хотите

  • ускорить inference на Intel CPU / GPU / NPU;
  • оптимизировать deployment;
  • работать с моделями из ONNX и других фреймворков;
  • получить стабильную производительность на Intel hardware.
# pip install openvino-genai nncf optimum-intel
# конвертация + INT4-квантизация
$ optimum-cli export openvino --model Qwen/Qwen2.5-7B-Instruct \
    --weight-format int4 qwen2.5-7b-ov

# инференс: device="CPU" / "GPU" / "NPU"
pipe = openvino_genai.LLMPipeline("qwen2.5-7b-ov", device="GPU")
■ ■ ■14_intel_ovms.md

Intel stack: OVMS

OpenVINO Model Server (OVMS) — сервер для подачи модели через API.

Подходит, если нужно

  • несколько клиентов;
  • API вместо локального чата;
  • серверный сценарий;
  • масштабирование внутри компании.
# запуск LLM-сервера в Docker
$ docker run -d --rm -p 8000:8000 -v /models:/models:ro \
    openvino/model-server:latest --model_name qwen \
    --model_path /models/qwen2.5-7b-ov --task llm

# OpenAI-совместимый REST на :8000/v3, gRPC, метрики Prometheus

Intel stack: ONNX

ONNX — универсальный формат обмена моделью.

Почему важен

  • удобен для конвертации;
  • хорошо подходит как промежуточный формат;
  • часто используется в enterprise-пайплайнах;
  • совместим с OpenVINO и другими runtime.
# pip install onnxruntime-genai
$ python model_runner.py --model qwen2.5-onnx --device cpu
# device: cpu / cuda / dml (DirectML на Windows)
■ ■ ■16_pipeline.md

OpenVINO + ONNX + OVMS: типовой путь

Типовой pipeline:

  1. модель в исходном формате;
  2. конвертация в ONNX;
  3. оптимизация через OpenVINO;
  4. запуск локально или через OVMS;
  5. подключение клиента через API.
[исходная модель] ──> ONNX ──> OpenVINO IR (INT4/INT8) ──┬──> локальное приложение
                                                              └──> OVMS :8000/v3 ──> N клиентов

OpenVINO читает ONNX напрямую — конвертация часто занимает одну команду.

■ ■ ■18_model_compare.md

Как сравнивать модели между собой

Сравнивайте не только «умность», но и:

  • качество ответов;
  • скорость генерации (tok/s);
  • память;
  • длину контекста;
  • поддержку tool use;
  • multilingual performance;
  • качество кода.
для реальной оценки делайте тест
  • 3–5 одинаковых промптов;
  • одинаковое квантование;
  • одинаковое железо;
  • одинаковый context length.
