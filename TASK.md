# TASK.md — Задание: одностраничный сайт превентивной медицины на локальном LLM

## 1. Что строим

За **30 минут** — **одностраничный сайт** на **превентивную медицину** (профилактику):
**один файл `index.html`** (HTML + CSS + JS внутри), без сборки и без зависимостей.
Пользователи заполняют форму прямо в браузере, сайт отправляет запрос в **локальный LLM**
и показывает персональный профилактический план: физическая активность, питание,
профилактические обследования, режим сна.

**Главная ценность:** всё работает на машине пользователя — данные не покидают устройство.

## 2. Что нужно участнику

- браузер и текстовый редактор;
- **не нужно**: Node.js, npm, сборщики, фреймворки, учётки на облачных LLM.

## 3. Инфраструктура (уже готова, трогать не нужно)

LLM-сервер запущен организаторами:

```bash
docker compose --profile llama up -d   # Gemma 4 E2B (Q4_0)
docker compose --profile tiny  up -d   # Llama 3.2 1B Instruct (Q4_0) — для слабых машин
```

- **API:** OpenAI-совместимый — `http://localhost:8000/v1`
- **Список моделей / проверка живости:** `curl http://localhost:8000/v1/models` → возьмите `data[0].id`
  (профиль `llama` даёт `gemma-4-E2B-it-Q4_0`, профиль `tiny` — `llama-3.2-1b-instruct`;
  поэтому id всегда узнаётся в рантайме)
- **CORS:** разрешён по умолчанию — запросы из браузера работают без настройки

Для кодинга доступен агент **opencode**: `docker compose run --rm opencode`.

## 4. Технологические правила (обязательные)

1. **Одна страница = один файл.** Весь сайт — `index.html` со встроенными `<style>` и `<script>`
   (чистый JavaScript + `fetch`). Фреймворки, сборка и npm — **не используются**.
2. **Сайт без сервера.** Никакого backend/прокси. Файл просто открывается в браузере
   (`file://` или любая локальная раздача статики, например `python3 -m http.server 8080` —
   опционально, если браузер блокирует fetch с `file://`).
3. **Все запросы к модели — из браузера клиента**, напрямую на `http://localhost:8000/v1`
   (OpenAI-совместимый `POST /v1/chat/completions`). Никаких промежуточных сервисов:
   промпты не покидают машину пользователя.
4. **Model id** узнаётся в рантайме через `GET /v1/models` (не хардкодить тег — под
   профилями `llama`/`tiny` модели разные).
5. Никакие данные не отправляются куда-либо, кроме `localhost:8000`.

## 5. Форма и сценарий

Обязательные элементы формы:

- возраст (число);
- уровень активности (select: низкий / средний / высокий);
- цели профилактики (checkboxes: двигательная активность / питание / профилактические обследования / сон);
- свободное поле «самочувствие, жалобы, образ жизни» (textarea) — **именно оно используется для red flag-теста**;
- кнопка «Составить план».

По отправке: строится промпт → `POST /v1/chat/completions` → ответ LLM выводится на странице.
Укажите, что генерация может занять десятки секунд — покажите статус «думаю…» и держите UI отзывчивым.

## 6. Безопасность и UX

1. **Дисклеймер** на странице с выдачей (обязательный текст дословно):
   «Материал носит образовательный характер и не является медицинской рекомендацией.»
2. **Red flags проверяются ДО отправки запроса к LLM** локальной JavaScript-функцией
   (например `isRedFlag(text)`). Минимальный список: боль в груди, одышка, кровотечение,
   потеря сознания, суицидальные мысли, температура выше 39 °C, острая боль в животе,
   признаки инсульта (асимметрия лица/рук, расстройство речи). При совпадении: план
   НЕ генерируется, показывается красный баннер «немедленно обратитесь к врачу / 103»,
   обращение к модели не выполняется.
3. Если LLM недоступен — понятный статус ошибки («LLM недоступен…»), не пустой экран и не вечный лоадер.

## 7. Самопроверка (браузерная, без инструментов)

Перед сдачей проверьте себя в браузере:

- [ ] форма отправляется, появляется статус «думаю…», затем план;
- [ ] «боль в груди» в поле жалоб → красный баннер, запрос к LLM **не** отправляется;
- [ ] дисклеймер дословно виден на странице;
- [ ] при выключенном LLM — внятное сообщение об ошибке, страница не «падает»;
- [ ] все сетевые запросы идут только на `localhost:8000` (вкладка Network в DevTools).

## 8. Критерии оценки

| Критерий | Вес |
|---|---|
| Работоспособность: форма → внятный персональный план | высокий |
| Red flag → совет врача, без генерации плана | высокий |
| Дисклеймер и корректный системный промпт | высокий |
| Приватность: запросы только на `localhost:8000`, фреймворки/сервера нет | высокий |
| UX: состояние загрузки/ошибки, читаемость плана | средний |
| Качество формулировки промпта (конкретный, структурированный план) | средний |

## 9. Порядок сдачи (пошаговая инструкция для участника)

Репозиторий хакатона: **https://github.com/extube/lllm.git**

### Шаг 1. Склонируйте репозиторий

```bash
git clone https://github.com/extube/lllm.git hackathon
cd hackathon
```

### Шаг 2. Запустите LLM на порту 8000

**Вариант A — docker-compose из репозитория (рекомендуется):**

```bash
docker compose --profile tiny up -d    # слабый ноутбук: Llama 3.2 1B Instruct (Q4_0, 773 МБ)
# или
docker compose --profile llama up -d   # Gemma 4 E2B (Q4_0, 2.84 ГБ)

curl http://localhost:8000/v1/models   # убедиться, что модель отвечает
```

**Вариант B — своя локальная модель** (что угодно с OpenAI-совместимым API на `:8000`):

- Ollama: `OLLAMA_HOST=0.0.0.0:8000 ollama serve`, затем `ollama run <модель>`;
- LM Studio: Developer → Local Server → порт 8000 (эндпойнт `/v1`);
- llama-server: `llama-server -m model.gguf --host 0.0.0.0 --port 8000`.

### Шаг 3. Создайте папку со своим именем и сайт

В корне проекта — папка с вашим ником (латиницей, без пробелов), внутри — ваш `index.html`:

```bash
mkdir ivanov && cd ivanov        # ← ваше имя
# откройте папку в редакторе, создайте index.html и пишите
# открыть сайт: двойной клик по index.html или python3 -m http.server 8080
```

Требования — разделы 4–6. Системный промпт, список red flags и логику промпта
можно взять из локального примера (раздел 10).

### Шаг 4. Самопроверка

Пройдите чеклист из раздела 7 прямо в браузере.

### Шаг 5. Pull Request в репозиторий хакатона

1. Закоммитьте свою папку в отдельную ветку:

```bash
git checkout -b ivanov-site        # ← ваше имя
git add ivanov
git commit -m "Add prevention site by ivanov"
```

2. **Если у вас нет прав на push в `extube/lllm`** (обычный случай):
   - на GitHub нажмите **Fork** на странице https://github.com/extube/lllm;
   - добавьте свой форк как remote и запушьте ветку:

   ```bash
   git remote add fork https://github.com/<ваш-логин>/lllm.git
   git push -u fork ivanov-site
   ```

   - откройте Pull Request: base = `extube/lllm`, ветка `main`; compare = ваша ветка
     `ivanov-site` из форка. В описании PR — что сделано + скриншот.

3. **Если у вас есть collaborator-права:** `git push -u origin ivanov-site`, затем
   кнопка «Compare & pull request» на GitHub (base `main` ← ваша ветка).
