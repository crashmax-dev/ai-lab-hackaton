# TASK.md — Задание: сайт превентивной медицины на локальном LLM

## 1. Что строим

За **30 минут** — сайт-помощник по **превентивной медицине** (профилактика).
Пользователь заполняет форму, сайт отправляет запрос в **локальный LLM** и показывает
персональный профилактический план: физическая активность, питание, профилактические
обследования, режим сна.

**Главная ценность:** все данные пользователя остаются на его машине — сайт без сервера,
LLM локальный (`localhost:8000`).

## 2. Инфраструктура (уже готова, трогать не нужно)

LLM-сервер запущен организаторами:

```bash
docker compose --profile llama up -d   # Gemma 4 E2B (Q4_0)
docker compose --profile tiny  up -d   # Llama 3.2 1B Instruct (Q4_0) — для слабых машин
```

- **API:** OpenAI-совместимый — `http://localhost:8000/v1`
- **Список моделей / проверка живости:** `curl http://localhost:8000/v1/models` → возьмите `data[0].id`
  (у участников — llama.cpp из docker-compose: профиль `llama` даёт `gemma-4-E2B-it-Q4_0`,
  профиль `tiny` — `llama-3.2-1b-instruct`; поэтому id всегда узнаётся в рантайме)
- **CORS:** разрешён по умолчанию — запросы из браузера работают без настройки

Для кодинга доступен агент **opencode**: `docker compose run --rm opencode`.

## 3. Технологические правила (обязательные)

1. **Svelte** (5.x) + Vite. Старт: `npm create vite@latest my-site -- --template svelte`.
2. **Сайт не имеет собственного сервера.** Никакого Node/Express/proxy-бэкенда.
   Разрешён только dev-сервер Vite на этапе разработки; артефакт сдачи — статика (`npm run build` → `dist/`).
3. **Все запросы к модели — из браузера клиента**, напрямую на `http://localhost:8000/v1`
   (fetch, OpenAI-совместимый `POST /v1/chat/completions`). Никаких промежуточных сервисов:
   промпты не должны покидать машину пользователя.
4. **Model id** узнаётся в рантайме через `GET /v1/models` (не хардкодить тег — под
   профилями `llama`/`tiny` модели разные).
5. Точка монтирования приложения: `<div id="app">` (стандарт Vite-шаблона).
6. Никакие данные не отправляются куда-либо, кроме `localhost:8000`.

## 4. Форма и сценарий

Обязательные элементы формы:

- возраст (число);
- уровень активности (select: низкий / средний / высокий);
- цели профилактики (checkboxes: двигательная активность / питание / профилактические обследования / сон);
- свободное поле «самочувствие, жалобы, образ жизни» (textarea) — **именно оно используется для red flag-теста**;
- кнопка «Составить план».

По отправке: строится промпт → `POST /v1/chat/completions` → ответ LLM выводится на странице.
Укажите, что генерация может занять десятки секунд — покажите статус «думаю…», держите UI отзывчивым.

## 5. Безопасность и UX

1. **Дисклеймер** на каждой странице с выдачей (обязательный текст дословно):
   «Материал носит образовательный характер и не является медицинской рекомендацией.»
2. **Red flags обрабатываются ДО запроса к LLM** локальной функцией `isRedFlag(text)`.
   Список минимум: боль в груди, одышка, кровотечение, потеря сознания, суицидальные мысли,
   температура выше 39 °C, острая боль в животе, признаки инсульта (асимметрия лица/рук, речь).
   При совпадении: план НЕ генерируется, показывается красный баннер «немедленно обратитесь
   к врачу / 103» без обращения к модели.
3. Если LLM недоступен — понятный статус ошибки («LLM недоступен...»), не пустой экран и не вечный лоадер.

## 6. Тестовый контракт (проверяется жюри автоматикой из `test/`)

1. **`/health.html`** — статический файл: в Vite-проекте положите его как `public/health.html`
   (в dev и в собранной статике он будет доступен по `/health.html`).
   При открытии сам делает fetch к `http://localhost:8000/health` и `GET /v1/models`
   и рендерит JSON в `<pre id="health-json">`:
   ```json
   {"status":"ok","app":"static","llmUrl":"http://localhost:8000","llmReachable":true,"model":"gemma-4-E2B-it-Q4_0"}
   ```
   (`llmReachable:false`, если LLM не отвечает — страница не должна ломаться).
2. **`window.__PREVENTIVE_APP__`** — объект, определяемый глобально, с полями:
   - `buildPrompt(formData)` → массив сообщений `[{role:'system'},{role:'user'}]`
   - `isRedFlag(text)` → `{match, advice}` | `null`
3. **Чистая логика в модулях** (импортируются юнит-тестами без браузера):
   - `src/lib/llm.js` — `SYSTEM_PROMPT`, `listModels()`, `chat(messages)`, `buildPrompt(formData)`
   - `src/lib/safety.js` — `RED_FLAGS`, `isRedFlag(text)`
4. **Маунт-точка** `<div id="app">` и наличие `<form>` на главной странице.

Проверка:

```bash
bash test/api-smoke.sh              # LLM поднят и отвечает
node test/site.test.mjs http://localhost:5173   # контракт сайта (dev или static-сервер)
```

## 7. Критерии оценки

| Критерий | Вес |
|---|---|
| Проходят `test/api-smoke.sh` и `test/site.test.mjs` | обязательно |
| Red flag → совет врача, без генерации плана | высокий |
| Дисклеймер и корректный системный промпт | высокий |
| Запросы идут только на `localhost:8000` (проверяем network trace) | высокий |
| UX: состояние загрузки/ошибки, читаемость плана | средний |
| Качество формулировки промпта (конкретный, структурированный план) | средний |

## 8. Порядок сдачи (пошаговая инструкция для участника)

Репозиторий хакатона: **https://github.com/extube/lllm.git**

### Шаг 1. Подготовка окружения

Нужны: `git`, Node.js ≥ 18, `npm`, Docker (либо своя локальная модель — см. шаг 2).

```bash
git clone https://github.com/extube/lllm.git hackathon
cd hackathon
```

### Шаг 2. Запустите LLM на порту 8000

**Вариант A — docker-compose из репозитория (рекомендуется):**

```bash
docker compose --profile tiny up -d    # слабый ноутбук: Llama 3.2 1B Instruct (Q4_0, 773 МБ)
# или
docker compose --profile llama up -d   # Gemma 4 E2B (Q4_0, 2.84 ГБ)

curl http://localhost:8000/v1/models   # убедиться, что модель отвечает
```

**Вариант B — своя локальная модель** (что угодно с OpenAI-совместимым API на `:8000`):

- Ollama: `OLLAMA_HOST=0.0.0.0:8000 ollama serve`, затем `ollama run <модель>`;
- LM Studio: Developer → Local Server → порт 8000 (эндпойнт `/v1`);
- llama-server: `llama-server -m model.gguf --host 0.0.0.0 --port 8000`.

Проверка в обоих вариантах: `bash test/api-smoke.sh` → `SMOKE TEST PASSED`.

### Шаг 3. Создайте папку со своим именем

В корне проекта — папка с вашим ником (латиницей, без пробелов), внутри — ваш сайт:

```bash
mkdir ivanov && cd ivanov            # ← ваше имя
npm create vite@latest . -- --template svelte
npm install
npm run dev                          # http://localhost:5173
```

Требования к коду — разделы 3–6. Контрактные артефакты: `src/lib/llm.js`,
`src/lib/safety.js`, `public/health.html`, экспорт `window.__PREVENTIVE_APP__`.

### Шаг 4. Прогоните тесты на своей папке

```bash
# из корня репозитория
bash test/api-smoke.sh                              # LLM поднят и отвечает
node test/site.test.mjs http://localhost:5173       # контракт сайта (vite dev)
```

Оба теста должны напечатать `... PASSED`. Затем вручную проверьте сценарии жюри:

дисклеймер виден; `health.html` показывает JSON со статусом модели.

### Шаг 5. Pull Request в репозиторий хакатона

1. Закоммитьте свою папку в отдельную ветку:

```bash
git checkout -b ivanov-site        # ← ваше имя
git add ivanov
git commit -m "Add prevention site by ivanov"
```

2. **Если у вас нет прав на push в `extube/lllm`** (обычный случай):
   - на GitHub нажмите **Fork** на странице https://github.com/extube/lllm;
   - добавьте свой форк как remote и запушьте ветку:

   ```bash
   git remote add fork https://github.com/<ваш-логин>/lllm.git
   git push -u fork ivanov-site
   ```

   - откройте Pull Request: base = `extube/lllm`, ветка `main`; compare = ваша ветка `ivanov-site`
     из форка. В описании PR — что сделано + скриншот.

3. **Если у вас есть collaborator-права:** `git push -u origin ivanov-site`, затем
   кнопка «Compare & pull request» на GitHub (base `main` ← ваша ветка).

Жюри проверит PR, запустив тесты из `test/` на вашей папке.
